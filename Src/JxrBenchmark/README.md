# JPEG-XR decoder benchmark

This Windows executable benchmarks libCZI's jxrlib and WIC decoders using the default
image generated by `WicJpgXrBenchmark`: 2048x2048 Gray16, lossy quality 0.9.
The exact JPEG-XR bytes are stored in `wpf-default-gray16.jxr` and embedded as
a Windows resource, so the executable can run without the image file.

Configure the libCZI CMake project with `LIBCZI_BUILD_JXR_BENCHMARK=ON` and
build the `JxrBenchmark` target in Release x64. For example, from a Visual
Studio developer prompt, with the libCZI dependencies configured:

```powershell
cmake -S . -B .\out\build\jxr-release -G Ninja -DCMAKE_BUILD_TYPE=Release -DLIBCZI_BUILD_JXR_BENCHMARK=ON -DLIBCZI_BUILD_UNITTESTS=OFF
cmake --build .\out\build\jxr-release --target JxrBenchmark
.\out\build\jxr-release\Src\JxrBenchmark\JxrBenchmark.exe
```

For comparison, use the same fixture with the WPF benchmark on the same machine:

```powershell
WicJpgXrBenchmark.exe --input .\Src\JxrBenchmark\wpf-default-gray16.jxr --warmup 5 --iterations 50
```

The executable checks each decoder's packed pixel SHA-256 against the WPF-decoded
reference and prints hashes of both the encoded bytes and decoded pixels.
It performs five warmups and 50 measured full decodes per decoder. Decoder
objects and the WIC factory are created before timing; each measurement includes
decoder initialization for the image and bitmap allocation. Resource loading,
COM initialization, pixel packing and hashing are excluded. Both measurements
use libCZI's decoder wrappers; earlier versions measured jxrlib directly.
WPF and native wrapper overheads differ, so this is a ballpark comparison
rather than a measurement of ZEN's end-to-end performance.
